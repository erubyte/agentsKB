# Bookmark triage and removal

The user authorized reviewing their X bookmarks, cataloguing coding/agent-development best practices with discussion context, and removing those bookmarks after preservation. Relevant AI-built project examples should be indexed and retained on X.

## Decisions

- Practice: an actionable coding or agent-development technique. Review source, parent/quote context, and accessible useful replies; preserve in the KB before removal.
- Project example: a demonstration of something built with AI. Index when relevant; always retain the bookmark, even if the post also teaches a technique.
- Resource/announcement: retain unless it actually supplies qualifying practical guidance. A tool launch alone is not a best practice.
- Unrelated or ambiguous: retain. Do not publish an inventory of unrelated personal bookmarks.

## Order of operations

1. Capture exact source URL and classify it.
2. Read the main source and complete the accessible discussion review. Record limits honestly.
3. Commit the source, extracted guidance, and review status to the repo; verify the published content.
4. Only for qualifying practices, remove the specific bookmark in X.
5. Verify its button changes from Bookmarked to Bookmark and record the outcome. Never infer success from a click alone.

Keep materially unread/inaccessible candidates bookmarked for continuation. A documented accessible-view limit is not proof that all platform replies were read. Preserve original URLs so a removed bookmark can be recovered. Removing a bookmark does not delete or unlike the post.

Use small batches so interruption cannot cause removal before preservation. If an operation fails, leave its state pending rather than reporting it complete. Existing authorizations apply; do not ask the user to reconfirm each qualifying removal.
